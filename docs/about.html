About this reference

What this site is, where its numbers come from, and how to correct them.

What this is

An unofficial, community-maintained wiki about GameSir controllers. Everything useful about them is scattered across product pages, per-edition manuals, separate FAQ documents, measurement sites and forum threads, and the same handful of questions keep getting asked over and over. This is somewhere to put the answers.

It is not affiliated with, endorsed by, or operated by GameSir. Nothing is sold, sponsored or affiliate-linked, and there is no advertising: links to manufacturer pages are there so you can check a figure against its source. Launch prices are recorded as dated historical facts, since price is part of how these models line up against each other. Nothing is on offer.

Who writes it

Whoever turns up. The whole site is a data file, a generator and a stylesheet in a public Git repository, so editing it needs a GitHub account and nothing else. Every page has an “Edit this page on GitHub” link at the foot that opens the exact file its content came from — and, on a controller page, the exact line.

Contributions are attributed through the commit history. There is no editorial board to convince; the only real rule is the one below about sources.

Where the numbers come from

Specifications are compiled from published sources, in this order of preference:

  1. GameSir's official product pages, per-model manuals and FAQ documents
  2. Independent measurements published by gamepadla.com, which documents its methodology and test hardware
  3. Published reviews from established outlets
  4. Community troubleshooting threads — used only for problem reports, never for specifications

These figures are not first-hand testing. Nothing here was measured by the maintainers unless it says so. Manufacturer claims are labelled as claims. Independent measurements come from one unit on one firmware and can vary between units.

The diagrams

Every diagram is original line art, drawn from primitives by the site generator and coloured from the same palette as the page around it. None of it is GameSir photography, a GameSir render, or a trace of either, and no GameSir logo or marketing asset appears anywhere.

The controller views are schematics, not scale drawings. Which controls a diagram shows comes from the same sourced record as the specification table, so it shows two rear paddles and no latches when that is what the sources document. The contours, spacing and proportions are drawn for clarity, so do not measure them.

The drawings are also written out as standalone SVG files under assets/gamesir/ — controller views, component close-ups and the site's own mark — so they can be reused on their own.

How gaps are handled

Anything that could not be verified against a source is left blank and marked “not documented” rather than filled in with a plausible estimate. A wrong number in a troubleshooting guide costs somebody an afternoon.

  • Manufacturer claims (battery life, durability ratings, latency) are labelled as claims, not measurements.
  • Measured stick and latency figures come from gamepadla.com, which publishes its methodology and test hardware.
  • Measured values can vary between individual units and between firmware versions.

How to contribute

Corrections are welcome, especially from people who own the hardware. Three ways in, roughly in order of effort:

  1. Report it and let someone else write it. Open an issue saying what is wrong or which controller is missing. A rough note with a link beats nothing, and you do not need to know how the site is built.
  2. Edit a page in the browser. Use the “Edit this page on GitHub” link at the foot of any page. GitHub forks the repository and opens a pull request for you. Nothing to install, nothing you can break.
  3. Edit the data and rebuild. Clone the repository, change data/controllers.json, run node build.mjs and commit the regenerated docs/ alongside it. No dependencies.

Whichever route you take, a change needs a source: a link, a manual, a measurement, or a description of what your own unit does and how you tested it. First-hand measurements are especially valuable, since this wiki has none of its own, and they will be credited as first-hand. The only changes turned away are figures with no way to check them.

Licence and reuse

Reuse it. Two licences, because the repository is two things:

  • The wiki content — specifications, documented fixes, FAQ answers and page prose — is licensed under CC BY-SA 4.0. Credit “GameSir Wiki contributors” with a link back, and license what you build on it the same way.
  • The generator — the build script, the diagram code and the stylesheet — is licensed under MIT. If you want to run a sourced reference like this one for different hardware, that is the part to fork.

Two caveats. Neither licence grants trademark rights: “GameSir” and the product names belong to their owner. And cited sources are references, not redistribution — a manual linked from a source list stays the property of whoever published it.
